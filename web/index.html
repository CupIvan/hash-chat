архитектура

Два сервера, один браузер

01

CAS

Контент-адресуемое хранилище hash-server. Отдаёт объект по sha256 и сверяет адрес с содержимым — подменить незаметно нельзя.

02

hashchat

Сервер координации. Хранит только порядок: seq, цепочку prev и пару deviceHash → userHash. Сообщений у него нет.

03

Браузер

Считает канонический JSON, кеширует контент в IndexedDB и пересчитывает sha256 при каждом чтении.

скорость

Почему быстро

  • Хэш сразу. Адрес известен до сети: сообщение уходит сразу, контент доливается в CAS в фоне.
  • Кеш навсегда. CAS иммутабелен, поэтому IndexedDB-кеш sha256 → content не нужно инвалидировать.
  • Только хвост. Long-poll отдаёт один хэш, остальное клиент добирает по цепочке prev.

сообщение

Что уходит в ленту

{
  "ts": 1792496909824,
  "text": "привет",
  "author": "<deviceHash>",
  "prev": "<хэш предыдущего>"
}

Хэш этого JSON — адрес сообщения в CAS. prev входит в хэш, поэтому лента — цепочка.
